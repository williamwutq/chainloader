================================================================================
SAEF - Simplified AArch64 Executable Format
Version 1.0
================================================================================

0. SCOPE
--------------------------------------------------------------------------------
    - Architecture: AArch64, 64-bit only.
    - Endianness: little-endian.
    - Page size: 4096 bytes, fixed.
    - Linking: static executables, and dynamically-linked executables and
      libraries (section 8).
    - No compatibility with ELF, PE, Mach-O, or other page sizes.


1. FILE LAYOUT
--------------------------------------------------------------------------------

+--------------------------------------------------------------------+  offset 0
|  FILE HEADER (fixed, 64 bytes)                                     |
+--------------------------------------------------------------------+  offset 0x40
|  SEGMENT HEADER TABLE (phnum * 40 bytes)                           |
+--------------------------------------------------------------------+
|  SEGMENT #0 CONTENTS                                               |
|  SEGMENT #1 CONTENTS                                               |
|  ...                                                               |
|  SEGMENT #N CONTENTS                                               |
+--------------------------------------------------------------------+
|  AUXILIARY TABLE (auxnum * 32 bytes)  [optional]                   |
+--------------------------------------------------------------------+
|  AUXILIARY BLOCKS                                                  |
+--------------------------------------------------------------------+

A segment (section 3) is mapped into the process. An auxiliary block
(section 4) is not.


2. FILE HEADER (64 bytes, fixed size)
--------------------------------------------------------------------------------

  Offset  Size  Field           Notes
  ------  ----  --------------  ---------------------------------------------
  0x00    8     magic_version   8-byte tag, raw bytes, compared byte-for-
                                 byte. e.g. "SAEF0001" (4-byte format id +
                                 4-byte ASCII version, zero-padded). An
                                 unrecognized tag is rejected before
                                 anything else is read.
  0x08    8     entry           virtual address of entry point
  0x10    8     phoff           file offset of segment header table
  0x18    8     auxoff          file offset of auxiliary table, 0 = none
  0x20    4     phnum           number of segment header entries
  0x24    4     auxnum          number of auxiliary table entries
  0x28    1     flags           bit0    EXEC_BTI  (all code built with BTI)
                                 bit1    EXEC_PAC  (all code built with PAC)
                                 bit2    STRIPPED  (no SYMTAB/STRTAB present)
                                 bit3    HAS_DEBUG (debug aux blocks present)
                                 bits4-5 TYPE (2 bits):
                                           00 = EXEC
                                           01 = DYN
                                           10 = DATA (no entry point;
                                               entry must be 0)
                                           11 = reserved
                                 bit6    HAS_RELOC (RELOC aux block
                                         present, section 9)
                                 bit7    reserved, must be 0
  0x29    3     reserved        must be 0
  0x2C    4     header_crc32    CRC32C over bytes [0x00, 0x2C), computed
                                 with this field absent from the range
  0x30    8     module_id       packed [name_hash:48][major:8][minor:8]
                                 (section 8.1). All-zero = no module
                                 identity.
  0x38    8     got_vaddr       virtual address of the GOT (section 8.5),
                                 import_count 8-byte slots inside a
                                 normal R+W LOAD segment. 0 = no imports.


3. SEGMENT HEADER (40 bytes each, forms the segment header table)
--------------------------------------------------------------------------------

  Offset  Size  Field         Notes
  ------  ----  ------------  -----------------------------------------------
  0x00    1     type          0 = NULL (ignore)
                               1 = LOAD (mapped)
                               2 = reserved, unused
                               3 = TLS (per-thread template, section 8.6)
  0x01    1     flags         bit0 R, bit1 W, bit2 X, bits3-7 reserved = 0
  0x02    2     reserved      must be 0
  0x04    4     crc32         CRC32C of the file_size bytes of this
                               segment's on-disk content
  0x08    8     file_offset   offset of segment content within the file
  0x10    8     file_size     bytes stored on disk for this segment
  0x18    8     vaddr         virtual address this segment is mapped to;
                               for type=TLS, reinterpreted as required
                               alignment in bytes
  0x20    8     mem_size      bytes occupied in memory (>= file_size; the
                               tail [file_size, mem_size) is zero-filled)

  Page-alignment rule (mandatory):
      file_offset mod 4096 == vaddr mod 4096

  Segments are split by permission (R+X, R, R+W); the kernel cannot
  assign different protection to sub-page ranges. For type=TLS, R/W/X
  flags are ignored.


4. AUXILIARY TABLE ENTRY (32 bytes each)
--------------------------------------------------------------------------------

  Offset  Size  Field     Notes
  ------  ----  --------  -------------------------------------------------
  0x00    8     type_tag  8-byte tag, ASCII, zero-padded, compared
                          byte-for-byte, e.g.:
                             "SYMTAB\0\0"  symbol table (debug)
                             "STRTAB\0\0"  string table (debug)
                             "DBGLINE\0"   debug line info
                             "DBGINFO\0"   debug info
                             "BUILDID\0"   build identifier
                             "META\0\0\0\0" free-form key/value blob
                                           (section 7)
                             "NEEDED\0\0"  declared dependencies
                                           (section 8.3)
                             "EXPORT\0"    exported symbols
                                           (section 8.4)
                             "IMPORT\0\0"  imported symbols
                                           (section 8.5)
                             "RELOC\0\0\0" relocation entries
                                           (section 9)
                             "CCONV\0\0"   per-function calling
                                           convention info (section 10)
                           Unknown tags are skipped.
  0x08    4     crc32     CRC32C of the block's content
  0x0C    4     reserved  must be 0
  0x10    8     offset    file offset of the block
  0x18    8     size      size in bytes of the block

  A stripped binary (flags.STRIPPED = 1) has auxoff = 0, auxnum = 0.

  NEEDED, EXPORT, and IMPORT are read before entry when present. Other
  aux block types are not read by the load path.


5. SYMBOL TABLE ENTRY (24 bytes each; content of a SYMTAB aux block)
--------------------------------------------------------------------------------

  Offset  Size  Field        Notes
  ------  ----  -----------  -----------------------------------------------
  0x00    4     name_offset  byte offset into the associated STRTAB block
  0x04    1     info         low nibble = type   (1 FUNC, 2 OBJECT,
                                                   3 SECTION-equivalent,
                                                   4 FILE)
                              high nibble = binding (0 LOCAL, 1 GLOBAL,
                                                      2 WEAK)
  0x05    1     seg_index    index into the segment header table this
                              symbol belongs to; 0xFF = absolute/none
  0x06    2     reserved     must be 0
  0x08    8     value        virtual address
  0x10    8     size         size in bytes, 0 if unknown


6. INTEGRITY
--------------------------------------------------------------------------------
Algorithm: CRC32C (hardware CRC32 instructions on AArch64).

Coverage: header_crc32 covers the header; each segment's crc32 covers its
on-disk content; each auxiliary block's crc32 covers its content.

This is corruption detection only, not authentication. It does not
verify the file has not been deliberately modified. See VERIFIED
(section 8.5) for the corresponding authentication-dependent flag.


7. METADATA
--------------------------------------------------------------------------------
A METADATA aux block is a flat sequence of:

    uint16 key_len
    uint16 val_len
    bytes  key[key_len]      (UTF-8, no terminator)
    bytes  val[val_len]      (opaque)

repeated until the block's declared size is exhausted.


8. DYNAMIC LINKING
--------------------------------------------------------------------------------

  8.1  Module identifier (64 bits)

  Used both for a file's own identity (header field module_id) and for
  every reference to another file as a dependency:

    bits [63:16]  name_hash  48-bit hash of the module's name
    bits [15:8]   major      8-bit major version
    bits [7:0]    minor      8-bit minor version

  Patch version has no field here.

  Resolution rule: a reference to (name_hash=N, major=M, minor=m) is
  satisfied by a loaded module whose own module_id has the same
  name_hash and the same major, with its own minor >= m.

  module_id = 0 means the file has no module identity. A nonzero
  module_id makes a file something other files can declare as a
  dependency, regardless of flags.TYPE.

  8.2  Symbol hashes

  Every symbol referenced by sections 8.3-8.5 is identified by a
  64-bit hash, precomputed at build time. Independent of SYMTAB's
  name_offset (section 5).

  8.3  NEEDED aux block (type_tag "NEEDED\0\0")

  A flat array of module_id (8 bytes each; count = block size / 8).
  Each entry's minor field is the minimum minor required. A file with
  no dependencies has no NEEDED block.

  8.4  EXPORT aux block (type_tag "EXPORT\0")

  A sorted array of 24-byte entries, sorted as one unsigned 64-bit key
  over the first 8 bytes:

    Offset  Size  Field             Notes
    ------  ----  ----------------  -----------------------------------
    0x00    7     hash              56-bit truncated hash of the symbol
    0x07    1     introduced_minor  minor version that first exported
                                     this symbol; used by build tooling
                                     to compute NEEDED minor, not
                                     consulted by the loader
    0x08    8     value             virtual address of the symbol, or
                                     (if flags.TLS is set) an offset
                                     into this module's TLS template
    0x10    1     flags             bit0 TLS (thread-local variable)
                                     bits1-7 reserved
    0x11    7     reserved          must be 0

  8.5  IMPORT aux block (type_tag "IMPORT\0\0")

  A sorted array of 16-byte entries, sorted by library_id then hash:

    Offset  Size  Field       Notes
    ------  ----  ----------  ---------------------------------------
    0x00    8     library_id  module_id (8.1) this import resolves
                               against
    0x08    7     hash        56-bit truncated hash of the symbol
    0x0F    1     flags       bit0 WEAK      unresolved import is not
                                              a load failure; caller
                                              null-checks before use
                               bit1 TLS       resolves to an offset
                                              into the providing
                                              module's TLS template
                               bit2 VERIFIED  only resolve against a
                                              copy of library_id
                                              verified by some
                                              external mechanism not
                                              defined by this format;
                                              an unverified match
                                              counts as unresolved
                               bits3-7 reserved, must be 0

  Entry i resolves into GOT slot i (header field got_vaddr). No
  relocation-type field, no PLT: every import is resolved before
  entry is reached; calling through an import is "load GOT[i], branch".

  GOT is R+W until resolution, then may be mprotected read-only.

  8.6  Thread-local storage

  A segment with type=TLS: file_offset/file_size are the initial
  contents, mem_size is the total per-thread block including the
  zero-fill tail, vaddr is the required alignment.

  TLS layout is static: computed once, before entry, by walking each
  loaded module's TLS segment in a fixed order and assigning each a
  disjoint offset range in one contiguous per-thread block.

  8.7  This format does not specify which component performs
  resolution.


9. POSITION-INDEPENDENT RELOCATION (RELOC aux block, type_tag "RELOC\0\0\0")
--------------------------------------------------------------------------------

  Present if and only if flags.HAS_RELOC is set. Applies to any
  flags.TYPE (EXEC or DYN).

  When present, every vaddr-shaped value in the file (segment vaddr,
  entry, got_vaddr, and EXPORT.value) is a link-time offset assuming
  base 0, not an absolute address. The loader chooses one base
  (page-aligned, so the section 3 congruence rule still holds) and
  adds it uniformly to all of them, including to RELOC entries below
  before applying them.

  A RELOC block is a flat array of 16-byte entries:

    Offset  Size  Field   Notes
    ------  ----  ------  -----------------------------------------------
    0x00    8     offset  link-time address (base 0) to write to
    0x08    8     addend  value written is (chosen_base + addend)

  No symbol reference in either field; this covers only a module's own
  internal absolute-address data (e.g. a function pointer or vtable
  entry stored in .data). Anything needing a symbol lookup goes
  through IMPORT/GOT (section 8.5) instead.

  A RELOC entry's offset may land in a segment declared read-only. The
  loader maps that segment R+W, applies all entries targeting it, then
  mprotects it back to its declared flags -- the same pattern already
  used for the GOT (8.5).


10. CALLING CONVENTION DEBUG INFO (CCONV aux block, type_tag "CCONV\0\0")
--------------------------------------------------------------------------------

  A CCONV block is a flat sequence of variable-length records:

    cc_record:
      Offset  Size  Field        Notes
      ------  ----  -----------  --------------------------------------
      0x00    8     symbol_hash  same 64-bit hash space as 8.2
      0x08    4     record_size  total bytes in this record, header
                                  included
      0x0C    ...   cc_aarch64   as defined below

  urange16_t (4 bytes), bit granularity throughout:

    Offset  Size  Field   Notes
    ------  ----  ------  ---------------------------------------------
    0x00    2     start   starting bit offset
    0x02    2     length  length, in bits

  cc_registers (16 bytes):

    Offset  Size  Field           Notes
    ------  ----  --------------  --------------------------------------
    0x00    4     preserved_gpr   bitmask, bit N = x[N] preserved
    0x04    4     clobbered_gpr   bitmask, bit N = x[N] clobbered
    0x08    4     preserved_simd  bitmask, bit N = v[N] preserved
    0x0C    4     clobbered_simd  bitmask, bit N = v[N] clobbered

  cc_stack (16 bytes):

    Offset  Size  Field            Notes
    ------  ----  ---------------  -----------------------------------
    0x00    2     flags            bit0    NORETURN (function never
                                             returns)
                                    bits1-2 SP_STATE:
                                              0 = LEAF (SP unmodified)
                                              1 = FIXED (SP adjusted
                                                  once at entry, constant
                                                  until restore)
                                              2 = DYNAMIC (SP varies
                                                  during the function)
                                              3 = reserved
                                    bits3-15 reserved
    0x02    2     alignment        required stack alignment, bytes
    0x04    4     region_arg       urange16_t, stack-passed arguments
    0x08    4     region_spill     urange16_t, spill region
    0x0C    4     region_preserve  urange16_t, callee-preserved region

  cc_location (8 bytes):

    Offset  Size  Field  Notes
    ------  ----  -----  ------------------------------------------------
    0x00    2     reg    register index (0-31) for KIND=GPR/SIMD; byte
                          offset into cc_stack's region_arg/region_spill
                          for KIND=STACK
    0x02    2     flags  bits0-1 KIND: 0 GPR, 1 SIMD, 2 STACK, 3 OTHER
                          bits2-15 reserved
    0x04    4     range  urange16_t, bits of the logical value this
                          location covers

  cc_value (6-byte header + location_size * 8 bytes):

    Offset  Size  Field          Notes
    ------  ----  -------------  --------------------------------------
    0x00    2     size           size of the logical value, bits
    0x02    2     alignment      required alignment, bits
    0x04    2     location_size  number of cc_location entries following
    0x06    ...   parts[]        location_size * cc_location, embedded

  cc_aarch64 (variable length; the body of a cc_record):

    Offset  Size  Field         Notes
    ------  ----  ------------  ------------------------------------------
    0x00    16    registers     cc_registers
    0x10    16    stack         cc_stack
    0x20    2     input_count   number of cc_value entries following
    0x22    ...   inputs[]      input_count * cc_value, embedded
    ...     2     output_count  number of cc_value entries following
    ...     ...   outputs[]     output_count * cc_value, embedded

  All arrays are embedded inline; consumers walk sequentially using
  count fields (location_size, input_count, output_count).
